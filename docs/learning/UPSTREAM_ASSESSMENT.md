## Submodules and optional data

The primary Data-Driven MPC checkout has no required gitlink in the inspected source. Its existing AirSim/acados replacement uses the already pinned acados/HPIPM/BLASFEO installation, so no ROS/Gazebo stack is installed. Neural MPC pins ML-CasADi at `d381639b462b242a3b327d6fb8249ac3af6427dc` (MIT); its metadata/API must be reconciled with a prospective neural port rather than silently using a current version.

Learning-to-Fly pins RLtools `3a612e29582aa7b509bd4df8a04fb3a9dd2b2721`, controller `d52b11a03caa1dadaf6b6bf02f328719b5bdd215`, media and googletest separately. The inspected simulator explicitly maps normalized actions into RPM and models motor lag; deployment code performs its own motor conversion. Crazyswarm's Crazyflie client/firmware/radio pins are recorded separately. These stacks are not built or redistributed for this first GP case study.

No upstream pretrained weights or experimental datasets are downloaded or redistributed. Repository source licences do not automatically settle rights to separately distributed weights/data. In particular, the pinned Neural-Fly README has a use restriction even though no root LICENSE file is present; DATT has no explicit root licence found. Both remain read-only references in this delivery.

## Recommended sequence after this case study

First use the measured matched GP-NMPC result, including nominal degradation if observed. Next, if a second learned dynamics model is needed, fit a small MLP on exactly the same flight split and compare it through the same NMPC. RL tracking, Koopman prediction and online policy adaptation are separate cases requiring their own action contract, training budget, held-out tasks and paired evaluation. No success for those algorithms is claimed by completing the GP port.

# Upstream implementation candidates

Initial screening on 20 October 2026. Pin and inspect exact revisions before importing code. This table describes candidates and documentation, not completed integration or independent validation of their numerical performance.

| Source | Use in this project | Licence observed | Adaptation work |
| --- | --- | --- | --- |
| [Microsoft AirSim](https://github.com/microsoft/AirSim), [core APIs](https://microsoft.github.io/AirSim/apis/), [Python API](https://microsoft.github.io/AirSim/api_docs/html/) | Simulator bridge, state/rotor telemetry and motor commands; inspect installed SimpleFlight code | Verify installed checkout and patches | Check local motor order, force mapping, client/server capabilities and timing. General API prose can lag the Python API/source. |
| [FDCL uav_geometric_control](https://github.com/fdcl-gwu/uav_geometric_control) | Preferred reference for the standard Lee/Leok/McClamroch SE(3) controller; numerical code exists in Python/C++/MATLAB | MIT shown in repository; retain [LICENSE.md](https://github.com/fdcl-gwu/uav_geometric_control/blob/master/LICENSE.md) from selected revision | Select standard rather than silently mixing decoupled-yaw variants. Adapt thrust-axis and error conventions, feedforward derivatives and allocation. |
| [safe-control-gym](https://github.com/learnsyslab/safe-control-gym) | Reference numerical cores and design patterns for PID, LQR and linear MPC | [MIT](https://github.com/learnsyslab/safe-control-gym/blob/main/LICENSE) | Its environments/models are not AirSim. Extract only suitable numerical logic; derive the chapter-compatible quadrotor model and full wrench interface. A CartPole LQR example is not UAV validation. |
| [TinyMPC](https://github.com/TinyMPC/TinyMPC) | Optional constrained linear-MPC solver/reference, particularly for later embedded deployment | [MIT](https://github.com/TinyMPC/TinyMPC/blob/main/LICENSE) | Supply and validate the quadrotor prediction model, limits, reference handling and fallback. A solver alone is not a complete UAV controller. |
| [RPG quadrotor MPC](https://github.com/uzh-rpg/rpg_mpc) | Research reference for UAV nonlinear MPC; optional comparison of formulations | GPL-3.0 shown in repository | Its control interface and ROS/toolchain must be inspected. Prefer citing/analysing unless dependency and redistribution terms fit the chosen implementation. Do not label linear MPC as a reproduction of this code. |
| [PX4 Autopilot](https://github.com/PX4/PX4-Autopilot) | Reference for flight-specific cascades, rate control, actuator saturation and anti-windup | Verify selected source-file and repository licence | Its complete firmware/estimation stack should not be transplanted solely to obtain a PID loop. Ported fragments require provenance and convention checks. |

For disturbance rejection, Chapter 5.3.4 provides compensation structure and cites observer literature, but does not specify a full observer. The implementation agent must select and document an actual force/moment observer from primary literature, implement or adapt it with licence provenance, and compare the same nominal controller with compensation off/on. Do not substitute an unverified general-purpose repository solely because its README lists a disturbance observer.

Required per-component manifest fields: upstream URL, pinned commit, source paths, licence path, authors/paper citation, local destination, reuse/adaptation/original-implementation classification, input/output conventions, modifications and validation status.
